# @holtmail/web

The Holtmail web app: a calm, keyboard-first mail client for an archive, and the place where the owner sets everything up: archives, mail sources, uploads and people. Vite, React 19, TypeScript, Tailwind CSS v4, TanStack Router, Query and Virtual, Motion. It talks to the server only through [`@holtmail/api-client`](../../../packages/api-client/docs/README.md), takes components from [`@holtmail/ui`](../../../packages/ui/docs/README.md) and every color, size and duration from [`@holtmail/tokens`](../../../packages/tokens/docs/README.md).

## Commands

From the repository root:

- `bun run dev:web` — dev server; `/api` is proxied to `HOLTMAIL_SERVER` (default `http://127.0.0.1:8080`)
- `bun run build` — production build into `apps/web/dist`
- `bun run typecheck`, `bun run lint`, `bun run test`

## Routes

Code-based TanStack Router routes in `src/router.tsx`. Every mail route accepts `?m=<messageId>`, the open message, so a URL is a shareable view and back and forward move between messages.

## Sign-in

The mail routes check `GET /api/session` before they load (cached for the visit). On `401` the app asks `GET /api/setup`: while the instance has no users it goes to `/setup`, otherwise to `/login?next=<the requested path>`. `/setup` without a token explains that the setup link is in the server log; `/setup` once users exist goes to `/login`, and `/login` while signed in goes straight to `next`. A `401` from any data query later (an expired session) clears the cached session and goes to `/login?next=<current path>`; queries are never retried on a `4xx`.

Both screens are one narrow centered column: the wordmark with a hairline that draws itself, then title, lead and form rising in one after another with the expressive curve (fades only under reduced motion). Fields are Carbon-style (label above, filled field with a bottom rule), focus starts in the first field, `Enter` submits, the password has a visibility toggle, and the autocomplete hints are `username`, `current-password` and `new-password`. Setup shows a live hint until the password has 10 characters. Errors from the API show under the form and move focus back to the field to fix; a `429` reads "Too many attempts, try again in N minutes" from `Retry-After`. `next` is accepted only as a same-site path that is not `/login` or `/setup`.

The user menu at the right of the top bar shows the name and email, the theme (light, dark, system) and Sign out, which posts `/api/logout`, drops every cached query and goes to `/login`.

## Setting up

Nothing needs the command line. After the owner account is created, `/` finds no archive and opens `/welcome`: an archive name (prefilled "Personal") and two large choices, Connect a mailbox and Import files, with a hairline that draws under the hovered one. Each step slides in from the right.

- **Connect a mailbox** asks only for the address and password. The domain picks a preset (Gmail, Outlook, iCloud, Yahoo, Fastmail, Yandex, Mail.ru, GMX, Proton Mail Bridge; `src/lib/providers.ts`), or `imap.<domain>` otherwise, and the password field explains where to get an app password, with a link. Server settings (host, port, TLS / STARTTLS / none, user name, sidebar name) fold open on demand and open by themselves when signing in fails for an unknown provider. The server signs in before saving, so a wrong password shows its reason under the form.
- **JMAP**: _Connect over JMAP instead (Fastmail and others)_ under the IMAP form switches to the JMAP form, and _Connect over IMAP instead_ back (`src/manage/connect-mailbox.tsx`). The JMAP form (`connect-jmap.tsx`, request built by `src/lib/jmap.ts`) starts with a provider choice: _Fastmail_ asks only for an API token (sent to `https://api.fastmail.com/jmap/session` as a bearer token, with a hint where Fastmail creates one) and an optional name (`Fastmail` when empty); _Other JMAP server_ asks for the JMAP address (session address or the server's address), _Password_ or _API token_, the user name for a password, the secret and a name. Empty fields are named under the form before anything is sent; the server signs in before saving and its reason shows under the form.
- **Gmail and Microsoft** addresses (`gmail.com`, `googlemail.com`, `outlook.com`, `hotmail.com`, `live.com`, `msn.com`, `office365.com`; `src/lib/oauth.ts`) get Sign in with Google / Microsoft instead of a password, with an optional sidebar name and a quiet note that the consent screen names Thunderbird, whose public sign-in Holtmail borrows unless the server owner registered their own. Only providers `GET /api/oauth/providers` lists are offered (`useOAuthProviders`, all of them until the list arrives): an address of a provider the server turned off gets the password form, and neither the Graph link nor the switch to OAuth on an account appears without Microsoft. _Use an app password instead_ switches back to the IMAP form, and back again. Signing in calls `startOAuth` with the current path as `return_to`:
  - when the server needs a paste (Thunderbird's client, the default), the provider page opens in a new tab and the form becomes _Finish signing in_: a link to open the page again, the instruction to copy the address of the page that cannot be opened after allowing access, a field for it with a hint until it contains `code=` and `state=` (or `error=`), the time the sign-in expires, the server's error on failure, Start again, and Finish, which calls `finishOAuth` and then continues exactly like a connected IMAP account;
  - with the owner's own client the tab itself goes to the provider and comes back to the same page with `?oauth=done&account=<id>` or `?oauth_error=<reason>`. `useOAuthReturn` reads and strips those params. The first-run screen finds the archive of that account and shows the progress step, or returns to Connect with the error; Archives settings show a dismissible confirmation or error above the archives.
- **Microsoft Graph**: _Connect Microsoft 365 or Outlook.com through Microsoft Graph instead_ under the IMAP form (above the JMAP link, shown for every address, since Microsoft 365 mailboxes mostly use their own domains) switches to the Graph form (`connect-graph.tsx`), and _Connect over IMAP instead_ back. It asks for the address and an optional sidebar name, says it suits Microsoft 365 work and school mailboxes where IMAP is turned off as well as Outlook.com and Hotmail, shows the Thunderbird note, and Sign in with Microsoft calls `startOAuth` with `kind: 'graph'` (request built by `graphSignIn` in `src/lib/oauth.ts`, which refuses anything that is not an address). The paste step, own-client return and progress are the same as for Microsoft IMAP sign-in.
- **Import files** takes files dropped or chosen (`.mbox`, `.eml`, `.zip`, and address books and calendars as `.vcf` and `.ics`, alone or in a Google Takeout zip; files without an extension are tried as mbox). Contacts show up in Contacts, events in the Calendar. They upload one after another, each with a thin progress bar that turns green when the server has it.
- The last step lists the sources with a live status: a pulsing accent square while syncing with the count of new messages, then "Synced 2 minutes ago". The archive can be opened right away; folders and messages appear while the sync runs.

## Settings

Reached from the user menu, the command palette or the "Add mail" link at the bottom of the sidebar. A section nav on the left (a top tab row on narrow screens) with an accent bar that glides between sections.

- **Archives**: each archive with its totals, a menu to rename it, export it (an _Export_ submenu with _mbox file_ and _Zip of .eml files_, shown when it has messages) or delete it (deleting asks to type its name), its mail sources and a _Save remote images_ switch, which explains that images are stored once and warns that downloading tells senders the message was fetched. When on, a panel shows saved images, their size and failures, offers _Save images of older mail_ (with the number of messages archived before) and _Retry failed images_, and while one runs shows its progress with Stop and a link to Tasks. A source row shows its kind, address and live status; Sync now spins while it runs; the menu renames, pauses or resumes, changes the password, or the API token of a JMAP token account (checked by signing in; not offered for OAuth accounts, whose connection dialog has no password either), edits the connection (server, port, security, user name, excluded folders, optionally a new password, required with a short note as soon as the host or port differs from the saved one or the security drops to none; for OAuth accounts server, port and security are read-only with a note that the provider sets them; for JMAP accounts the address, _Password_ or _API token_, user name, excluded mailboxes and optionally a new secret, required when the sign-in kind changes or the address moves to another origin; the comparison is `src/lib/connection.ts`, the same rule the server enforces; checked by signing in), sets how often it checks for new mail (like the server, an interval, or only on request), sets _What to archive_ (all mail as it arrives, or only mail older than a week, 30 days, 90 days or a year; a value set from the CLI shows as its own choice; younger mail is archived by a later sync once it is old enough) or removes it (archived messages stay). The row shows when the next sync is due. JMAP accounts show "JMAP" next to their name, Graph accounts "Graph" (and "Microsoft sign-in"; their menu has _Sign in again_ and no connection to edit). OAuth accounts show "Google sign-in" or "Microsoft sign-in" and offer _Sign in again_ in the menu; when the provider stopped accepting the sign-in the status reads "Sign-in expired" in red (also in the sidebar) and _Sign in again_ replaces Sync now. Password accounts on Gmail or Microsoft servers offer _Switch to Google / Microsoft sign-in_. Both open a dialog that runs the same start, paste and finish flow for that account. _Archive contacts and calendars…_ (IMAP, JMAP and Graph accounts; Microsoft accounts over IMAP get a note to add the mailbox as a Graph account) opens a small dialog with an on/off switch: for password accounts an _Address_ field, prefilled for Fastmail, iCloud and Yandex (`src/lib/contacts-calendars.ts`) and otherwise empty with a hint that Holtmail looks it up from the mail domain or takes a Nextcloud-style `https://cloud.example.com/remote.php/dav`, and a _Calendars live at another address_ switch with a second field; the server signs in before saving and its reason shows under the form. For JMAP accounts the address field starts empty (no provider preset) with a hint that an empty address reads them through the JMAP server when it offers contacts, and a note when they are already read that way. For Google and Graph accounts the dialog says the provider asks once to allow access; _Turn on and sign in again_ saves and opens the sign-in dialog titled _Allow contacts and calendars_ (`asksConsent`). The dialog also takes an optional _CardDAV and CalDAV password_ for servers that want an app password (with a switch to go back to the account's own once one is stored). For a JMAP account a calendars address alone keeps contacts on JMAP and reads calendars over CalDAV, which the dialog then says; when the server found CalDAV calendars for a JMAP account without them (`caldav_offer`) it shows the address and _Read calendars over CalDAV_. While on, the row shows a second status line: syncing, synced some time ago, the last error, or, for a Google account still waiting, "sign in again to allow access" as a link to that dialog. _Watch for changes_ in the menu chooses _Inbox_ (_All mail_ for Gmail), _Chosen folders…_ (IMAP; a dialog with folder paths separated by commas) or _Only on schedule_; _Check contacts and calendars_ (while they are on) sets their own interval, from every minute to once a day, or like mail. Each status line shows its watch after the status (`src/lib/watch.ts`): _Live_ in green, _Connecting_, _Reconnecting_ in the warning color with the reason as a tooltip, or _Scheduled_ when the server cannot report changes. Tasks lists contacts and calendars syncs with their own icon. Above the archives, _Checking for new mail_ sets the interval for sources without their own, read-only when the server's config sets it. Connect a mailbox and Import files open the same forms as the first run in a dialog. New archive creates one and opens Connect for it.
- **People**: everyone who can sign in, with role and access. Add person sets email, name, a password to hand over, the role (members also get a checklist of archives). The row menu changes role, edits a member's archives, sets a new password (ending their sessions) or removes them. Only owners manage owners; nobody changes their own role or removes themselves.
- **Tasks**: the running tasks and the 200 most recent finished ones, also from before a restart, running first: kind and title, state badge (_Interrupted_ in the warning color, with a line saying that syncs run again on schedule and image downloads pick up where they stopped, for tasks a restart stopped), a progress bar (sliding while the amount of work is unknown), the summary, start time and duration, Stop for remote image tasks, and a collapsible log that follows new lines while scrolled to the end. The nav item shows how many are running, and so does a link at the bottom of the sidebar.
- **Integrity**: the ledger's newest position and hash with Copy (to keep somewhere else), the last check (entries, problems as a list of ids and positions, messages read), Check the ledger and Check with every message's bytes (each starts a `ledger_verify` task; a note links to Tasks), and an optional `position:hash` written down earlier.
- **Webhooks**: one card per webhook with its address (a note when it is not https), On switch, event checkboxes saved as they change, Send test, New secret (shows the new secret once), Remove (confirmed) and the newest deliveries (Delivered, Trying again or Gave up, attempts, last status or error), refreshed every 10 seconds; under them Add webhook with the address and events, which shows the signing secret once.
- **Aliases** (`aliases-page.tsx`, helpers in `src/lib/aliases.ts`): per archive (a picker when there are several). _Services_: one card per connected service with its provider, address, when its aliases were last listed or why that failed, _List now_, _New key_ and _Disconnect_ (confirmed, with a switch to keep its aliases as added by hand); _Connect a service_ picks a provider with an API, asks for its key (with where to find it), an optional name and an address for self-hosted ones. _Aliases_: a search over address, note, website, mailbox and account, pickers for the source (from services, added by hand, only in mail) and the provider, and one row per alias: the address, provider, a _N unsigned_ warning for aliases only seen in mail whose forwards carry no signature, a Forwarding switch when the service can switch it, the note, messages, senders, last mail and the service's own counts, website, reply name, the mailboxes it forwards to and the accounts its mail was archived from. The row menu has _Show mail_ (a `to:` search), _Edit_ (only the fields the service keeps; mailboxes as checkboxes) and _Delete_ (at a service that can, by typing the address; otherwise only forgetting it here). _New alias_ (when a service can create) chooses the service, picked by the service or an own prefix with a domain or suffix from the service, note, reply name, website and mailboxes. _Add by hand_ takes an address and a service (or another name) for Apple, DuckDuckGo or own domains.
- **SMTP**: read-only, since the listener lives in the server's config: where it listens, STARTTLS, TLS required and sign-in badges (a warning badge when neither TLS nor sign-in is on), accepted networks, the size limit, routes as recipient → archive / folder with "Exchange journal unwrapped", and the counters since the server started.
- **Network**: the image proxy. Shows the current address (credentials never come back), saves a new one after the server checks it accepts connections, removes it; read-only when the server's config sets it.
- **Reading**: remote images, kept in this browser (`localStorage`, `holtmail.remote-images`), because the address a sender sees depends on the device. _Hide, and ask each time_ (default), _Always show, through Holtmail_ (the server fetches them; senders see its address) or _Always show, directly_ (with a warning that senders see your IP address, rough location and when you open each message). Saved copies always show.
- **Profile**: name and email, and a password change that keeps this browser signed in and signs out the others.

While any source of the shown archive syncs or imports, the app refreshes its archive totals, folders and message list every four seconds, and everything once more when the run ends. An archive without messages shows "This archive is empty" with an Add mail button, or "Archiving mail…" while its first sync runs. The sidebar lists the archive's sources with their status squares.

Three panes: folders, message list, reader.

- From `68.75rem` (1100px): all three side by side.
- From `45rem` (720px): folders and list; the reader slides over the list and has a back button.

## Contacts

_Contacts_ sits under _All mail_ in the sidebar (`g c`, or the command palette) and uses the same three panes: the people list where messages are listed, the person where the reader is. The selected person is `?p=` in the URL, so `j`/`k`, `Enter`, `Esc` and `/` work as in mail and a person page is a link.

- **List.** People from [`/api/archives/{id}/people`](../../../crates/api/docs/README.md), by name, virtualized and loaded page by page like messages, as a `listbox` with the same gliding selection bar. Each row: a square with the initials (an icon when there is no name), the name (struck through when the person was removed) and, in mono, the first address or phone; at the right a hairline `≠` when the sources disagree, `×N` for several cards, a mail icon for people from mail alone, and the message count. The header shows the total, a download menu (_.vcf file_ with the latest version of each card, _Zip of every version_ with a manifest, for every contact or, while an address book filter is on, that address book; _Removed contacts too (.vcf)_ adds removed cards; plain links to `/api/archives/{id}/contacts/export`, `contactsScope` in `src/lib/export.ts`), a filter menu (source: everyone, with a contact card, from mail only, or one address book; _Sources disagree_; a small accent square on the button while filters are on) and a search field that filters as you type (200 ms) and keeps the text in `?q=`. When some people's sources disagree, a _≠ Differences N_ toggle under the title counts them for the current search and source and turns `?diff=` on or off (pressed while on); the count is the `total` of the same list with `has_differences`, so turning it on reuses the cached page.
- **Empty.** No people at all explains how to get some: import a `.vcf`, or turn on contacts and calendars for an account; owners and admins get buttons to both. No match offers _Clear filters_.
- **Person.** The initials, the name, the first address and phone as `mailto:` and `tel:` links, marks for the number of cards (or _From mail_), _Removed_ and _Sources disagree_, and which fields disagree. _Details_ lists every field: where the sources agree the value is shown once with small hairline source marks (account · address book); where they disagree each value is on its own line with its source and when it was last seen ("Work · work, seen today · Home · home, last seen 2024"), and the field has a `≠`. _Contact cards_ lists each source card with its address book, version count and last seen, linking to its history at `/items/$itemId`, and under it why the cards are one person ("same email ada@example.com: Ada Quill ↔ Ada Q."). _Correspondence_ gives the message counts (from them, to them), the first and last message, a hairline bar per year from the first to the last year, the conversations most recently active first (each opens its newest message in mail) and the files exchanged as attachment tiles. _Meetings_ lists events they organize or attend, newest first, with their answer, linking to the event. People from mail alone get a note on why they are listed instead of details. Under the marks, splits and joins made by hand that touch the person show as _Joined by hand_ or _Split by hand_ with the date, _Show the other person_ for a split, and _Undo_ for owners and admins (`overrideNotes` in `src/lib/people.ts`); a join also shows among the reasons as "joined by hand". Owners and admins get _Split…_ (with two or more cards: a dialog with a checkbox per card, enabled while at least one card stays on each side, `canSplit`) and _Join with…_ (a dialog that searches people as you type and joins with the one picked, `joinCandidates`); after either the lists refetch and the person shown is the one the server names (the rest after a split, the joined person after a join). A refused join (a split keeps them apart) shows the server's reason in the dialog. _Export cards_ downloads the person's cards as a `.vcf`, removed ones included.
- **Reader.** In an expanded message, every address that belongs to a person (`MessageDetail.people`) is a quiet underlined link to that person in Contacts; when the sender has a person, a _From_ line joins To and Cc so the sender can be followed too.

## Calendar

_Calendar_ sits under _Contacts_ in the sidebar (`g e`, or the command palette) and takes the whole space of list and reader. Instances come from [`/api/archives/{id}/calendar`](../../../crates/api/docs/README.md) for the span of the view in the viewer's zone (midnight to midnight, so a week across a daylight saving change is 167 or 169 hours); copies of one event in several calendars are one instance with a hairline "3 copies" mark (`×3` in the grids).

- **Header.** The span's title, _Today_, previous and next (a week in the week view, a month otherwise), a date field to jump to a day, the view toggle (Agenda, Week, Month) and a _Calendars_ menu: one checkbox per calendar with its color swatch and account ("From mail" for events found in invitations), _Show removed events_ and _Show all calendars_; a small accent square on the button while some are hidden or removed events are shown. Everything is in the URL.
- **Agenda** (the default, the most useful for an archive): the month's days that have events, each under a sticky mono day header (today marked in accent), each event a row with its time span in your zone (or _All day_), the calendar's color as a small square, the title (struck through when cancelled or removed) with the location under it, and the copies, _Cancelled_ and _Removed_ marks. An empty month says so.
- **Week**: a header of days (a click opens that day's week), an all-day row, then a 24-hour grid scrolled to 07:00 with hairline hour lines, a red hairline at the current time today, and events as blocks with the calendar color as a 2px left border; overlapping events share the day's width in columns (`layoutColumns`), events shorter than 15 minutes still get a 15-minute block, and events crossing midnight are cut per day.
- **Month**: whole weeks around the month, days outside it on the subtle background, today's number in an accent square, up to three events per day (all-day first) and "+N more", which opens that week.
- Dates stay on their dates in every zone, floating times read the same everywhere, and timed events are placed by their instant in your zone. Calendar colors are taken only when they are hex colors; a calendar without one gets a neutral swatch.
- **Event page** (`/events/$groupId`, a page of its own like the item page): the title with the number of copies and _Cancelled_; _When_ in your zone with the original zone underneath when it differs; _Repeats_ in words ("Every 2 weeks on Tuesday and Thursday, 5 times", `describeRecurrence` in `src/lib/recurrence.ts`), the rule as written, its exceptions, extra dates and changed dates; where; the organizer; the description. _Attendees_ is a table of people (linked to Contacts when a person has the address) with one answer column per copy, or one column for a single copy. _Copies_ lists each calendar with its swatch, account, _Shown_ on the leading copy (highest sequence, then the latest change), sequence, version count and a link to that copy's own history (`/items/$itemId`). _Differences between copies_ is a table of the fields that differ, one column per copy. _Mail_ lists the messages the event came in, each opening in the reader. _History_ merges every version of every copy, newest first, with the copy's calendar, method, date, raw download and changes.
- **Export.** A download button at the end of the calendar header offers _.ics file_ (the latest version of each event) and _Zip of every version_ for the events of the shown span (the shown calendar only when one is left on; removed events when _Show removed events_ is on), or for every calendar item of the archive. Plain links to `/api/archives/{id}/calendar/export` with `download`.
- **Links.** The invitation card's _Open event_ and a person's _Meetings_ open the event page (the card keeps _Mail history_ to the item page); meetings list copies of one event once.

## Message list

Virtualized with `@tanstack/react-virtual` and loaded page by page as the end comes into view. Rows are grouped by day with a sticky header: "Today", "Yesterday", the weekday within the last week, "12 March" this year, "March 2019" for older years (one group per month). Each row has the sender, the date (time today, weekday this week, day this year, short date before) in tabular mono, the subject, a one-line preview and a paperclip for attachments. In search results, a row whose words were found only inside an attachment (`attachment_match`) shows a quiet hairline chip "In attachment" with the paperclip instead. Unread rows (no `\Seen` in the folder shown, or in any folder for all mail and search) set sender and subject in medium weight and carry a small accent square at the left edge; read rows are regular weight with a muted sender. A star marks `\Flagged`, and a hairline badge with the count marks conversations of more than one message. A key glyph marks messages with a code (`insight_kinds` contains `code`), never the code itself. Labels show at the right of the subject as up to two quiet hairline chips (muted text, square, no fill) with `+N` for more; Gmail's system labels (Inbox, Starred, Important, Sent, Drafts, Spam, Trash) and the label being shown are left out, so only labels that tell something appear. List chips are plain text, not links, to keep the list a single `listbox`. The list is a `listbox`; the cursor is its `aria-activedescendant`, drawn as a selected background with a 2px accent bar that glides between rows and jumps without animation while the list scrolls.

While the list has rows, a download button at the right of the header exports what it shows: all mail, the folder, the label or the search. Its menu names what is exported and offers _mbox file_ (one file for mail clients and archivers), _Zip of .eml files_ (one file per message, in folders) and _Zip of PDFs_ (one PDF per message with the original inside); each is a plain link to `GET /api/archives/{id}/export` with `download`, so the browser streams the file to disk and the session cookie goes along. The address comes from `exportHref` in `src/lib/export.ts`. In search results owners and admins also get a bin button, _Delete these messages…_, which opens the deletion dialog (`src/manage/deletion-dialog.tsx`): it asks the server for a review (`POST /api/archives/{id}/deletions` with the query) and shows how many messages, their size, their date span, up to 20 of them and what deletion means, then asks to type the number; _Delete for good_ confirms the review and starts a `delete_messages` task.

## Reader

When an alias service forwarded a message (`MessageDetail.alias`), the sender it hid is shown in place of the reverse alias (in the summary, the From line and the reply's quote line; replies still go to `From`), and an _Alias_ line shows the alias (a link to its mail), the service, whether the service signed it or the alias is known, or a _Not verified_ badge with an explanation, its note, and the reverse alias replies go through.

Under the subject, the open message's labels as outline badges with a tag icon, system labels first; each is a link to that label's list.

The whole conversation (`/api/threads/{id}`), oldest first. The open message and the latest one are expanded; others are one line (sender, the message's `preview`, date) and expand in place. HTML bodies render in an iframe with `srcdoc`, `sandbox="allow-same-origin allow-popups allow-popups-to-escape-sandbox"` (no scripts), links opening in a new tab, resized to their content on load and on every `ResizeObserver` change. When the server left remote images out, a banner offers Show (this message, through the server's proxy) and Always show…, which opens Reading settings. When saved copies are shown, a quiet line says so and offers Load from sender (through the proxy, or directly when Reading says so) and back. Plain text keeps its line breaks and links. Attachments are square tiles with a hairline border: PNG, JPEG, GIF and WebP images show the server's thumbnail (`thumbnail_url`, at most 320 px, lazy-loaded, cropped to the square with `object-cover`), falling back to the type icon when the thumbnail does not load; everything else shows an icon by type. Types the server shows inline (PNG, JPEG, GIF, WebP, AVIF, PDF) open full size in a new tab; the rest download. A message with calendar parts shows one card per event above its body (`MessageDetail.invitations`): what the message is (Invitation, Answer, Cancellation, …), the summary (struck through with a Cancelled badge once cancelled), when in the viewer's zone with the organizer's zone and time underneath when they differ, where, the organizer, your answer when one of the archive's addresses is an attendee, "Updated N times since" and Open event, which goes to the event page (`/events/$groupId`), with _Mail history_ next to it for `/items/$itemId`. The card is a hairline box on the subtle background, square like everything else. Between the addresses and the invitation cards, an expanded message shows its insights card (`src/mail/insights-card.tsx`, from `MessageDetail.insights`) when there is something to show: nothing for `pending`, `unparsable` or `unreadable`, and `partial` or `outdated` the same as `ready`. Each code is a focusable row (`InsightRow` in `src/mail/row.tsx`, which also holds the `Row` the invitation card uses) in tabular mono, grouped for reading (six digits as 3+3, eight as 4+4, everything else as is) with a Copy button that copies it without spaces. A code more than 15 minutes old, counted from the earlier of `received_at` and `sent_at` (or with no time known), collapses to "Code from 3 days ago" with Show; the age is checked every 30 seconds and Copy still works collapsed. `↑` and `↓` move between rows, `Enter` reveals a collapsed code or copies it, and `c` on a row copies that row. The footer has the unsubscribe link (the https link, else the `mailto:`; a new tab with `rel="noopener noreferrer"` and `referrerpolicy="no-referrer"`), with why one-click is not offered in its tooltip, and a muted _Sender not checked_ while the sender's trust is unknown. The logic (order, grouping, freshness, reason text, which message a shortcut acts on) is in `src/lib/insights.ts`. The toolbar has Reply (`mailto:` to Reply-To or From with a `Re:` subject, `In-Reply-To` and `References` for the clients that honor them, and a body quoting the first eight lines of the text under "Sender wrote:"), Download `.eml`, Download PDF (`GET /api/messages/{id}/pdf`), View source, Copy link (the shared `CopyButton`: the Clipboard API, then `execCommand` so it works on plain HTTP, then the link selected in a field with Press Ctrl+C / ⌘C) and, for owners and admins, Delete for good, which opens the same deletion dialog for the one message and goes back to the list once the deletion started.

## Search and commands

The search field sits in the list header. `Enter` opens the search route, an empty query goes back to all mail, and a `400` from the API shows its message under the field. While the field is focused or a search is shown, a row of operators (`from:` `to:` `subject:` `has:attachment` `attachment:` `before:` `after:` `in:` `label:` `is:unread` `with:` `is:event` `is:contact`) inserts tokens at the caret. Search results start with up to five _Events and contacts_ found by the same query (`/api/archives/{id}/search/items`), each opening the event page or the person, and the count of the rest; mail follows as before, so `is:event` shows events and no mail. `⌘K` / `Ctrl+K` opens the command palette: run a search, jump to a folder, label or archive, go to contacts or the calendar, open settings, connect a mailbox, import files, sync every source now, export the archive as mbox or as a zip of `.eml` files, export its contacts as a `.vcf` or a zip of every version, export its calendar as an `.ics` or a zip of every version, toggle the theme, show shortcuts.

## Motion

Through `MotionProvider` and the token presets: the reader fades and rises 8px with the expressive curve when the selection changes; thread messages expand and collapse with height and opacity; the selection bar moves with the productive curve; panes and the folder sheet slide on narrow screens. Nothing in the list animates while it scrolls. With reduced motion, movement is dropped and height changes are instant.

Folders are grouped by account. Each shows its unread count emphasised next to the muted total; folders with nothing unread show the total only. Folders with a role come first (inbox, starred, important, drafts, sent, archive, all mail, junk, trash) and are never nested; the others follow alphabetically with natural number order and nest under their nearest existing parent path.

Archives with labels (Gmail) get a Labels section under the folders, with the same counts: Gmail's system labels first (Inbox, Starred, Important, Sent, Drafts, Spam, Trash), then the others by name with natural number order, nested under their nearest existing parent (`Work/Projects` shows as `Projects` under `Work`). The section is absent while the archive has no labels. Labels are refreshed with the folders while a source syncs.

## Theme

Chosen in the user menu or toggled from the command palette. The choice is stored in `localStorage` under `holtmail.theme` as `light` or `dark`; `system` removes the key. `light` and `dark` set `data-theme` on `<html>`; `system` removes it and the tokens follow `prefers-color-scheme`. Every storage access is wrapped in `try`/`catch`.
